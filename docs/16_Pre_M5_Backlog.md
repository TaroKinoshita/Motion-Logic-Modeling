# M5着手前の残作業

棚卸し時点の記録。以後に完了した実装・検証と持ち越しは[輪郭と動きの改訂結果](17_Contour_Blocking_Result.md)を参照。

現在の4面比較は `Lyricsample1` 全編7.625秒を再生・出力できる。ブロックの軌道を元映像から起こしたのは0〜26Fで、27F以降は既存シーンで補完した。背景反転の時刻は全編で実測した。「食＋反→飯」の10フレームの外形計測と合字規則による比較版は、従来の文字シーンで検証済み。新しいブロック・出来事・外観の工程には未接続。 [初版の比較結果](15_Blocking_Preview_Result.md)・[従来の合字規則の検証](13_Lyricsample1_Meshi_Rule.md)

## 1. M1・M2　実素材のブロック工程を最後まで通す

- [ ] **同条件で採点する。** 冒頭と中盤の代表コマの位置・外形、表示端、接触、本当に判別できない状態を人が元動画だけで先に記録する。フレーム番号、時刻、入力SHA256、対象ID、根拠を保存する。中心誤差の中央値は画面対角の1%以内（約22px）、幅・高さの相対誤差の中央値は各10%以内、主要イベントは±1Fを初回目安とする。1Fしかないイベントは完全一致を別記し、欠測率・最大誤差・ID取り違え・過剰統合を出す。
- [ ] **「食＋反→飯」を二つ目の検証区間にする。** 71〜93F付近で、部品の独立軌道、81Fの接触／合字の見え方、82Fの白黒反転、92Fの「食反」、93Fの反転解除を照合する。旧版の10F分の計測結果を比較基準に使う。接触で見えなくなった部品は遮蔽・欠測を記録し、合体・分離・一時的な重なりは人が確認する。
- [ ] **範囲指定とIDの連続性を一般化する。** 素材専用のフレーム別ROIを、最初の範囲指定と部分修正で回せる形にする。近接と数コマにわたる相対運動を使ってブロック候補を作る。後から文字／部首／ルビへ分割できるよう成分を保持。粒子は必要に応じ群として扱い、ばらばらに動く成分は保持する。切替で探索を区切り、クリップ・欠測・再捕捉・遮蔽の理由を出す。
- [ ] **動きの質を採点する。** 原寸の中心・幅・高さと、速度、方向転換、停止長、加減速を比較する。従来の領域追跡で検証したキー近似をブロックにも使い、誤差上限を守りながら線形／単調cubicとキー数を比較する。回転のある「何にも」で角度を検証し、角度が一意に測れないコマは欠測。「各」の縦軸回転は見かけの横幅として保持する。
- [ ] **カメラ候補を確認する。** 画面上で離れた複数の軌道から共通変換と残差を出す。人が適用を確認したら、元の画面上の位置が変わらないよう各フレームの子を親の逆変換で変換する。支持する軌道が足りない場面は画面座標のまま使う。
- [ ] **全編に広げる。** 「田＋丁」、文字の登場順、ルビ、線・粒子、後半の流し・寄りに適用。区間ごとの実測・補完・手修正・欠測を表示する。白黒反転4件の検出は確認済みなので、追加素材で誤検出を調べる。
- [ ] **最終調整を同じグループにつなぐ。** 文字、ルビ、図形を同じ動きの子として管理し、外接寸法と継承する拡縮を分離。書体・字間・太さと外観差し替え後の接触を確認する。重要な回転や変形は必要な範囲で近似し、再現できない箇所を記録する。4面比較・単独版・編集できるシーンを再出力する。

## 2. M2　人が直して再計算できるようにする

- [ ] 工程比較画面で元動画を拡大し、座標を見ながら範囲を選び、短区間を解析する。フレーム移動、候補の点検、元成分への分割、箱とIDの修正、誤追跡除外、部分的な再計算を扱う。フレーム／カット吸着は既存の操作を利用する。
- [ ] 出来事の対象・時刻・根拠を見せ、候補の確定・却下とフレーム単位の編集を可能にする。観察・ブロック・出来事・外観を版管理し、UIとMCPから同じ変更を行えるようにする。再解析時は手修正を保護し、衝突や参照切れを検知する。巻き戻し・再読込・再出力も確認する。
- [ ] 追跡の共通出力を揃える。OpenCV・手修正・必要なモデルが、フレーム、対象ID、中心、外形、可視状態と欠測理由、手法と設定を同じ形式で返す。生の観測とキーへの近似を別に保存し、残す／統合／置換／省略した判断も記録する。
- [ ] 工数を同じ条件で測る。直接文字を起こす場合とブロック経由で、準備、範囲選択、観測、キー修正、目視確認までの作業時間、手修正回数、要素・キー数を比較する。SSIMは外観まで付けた版の補助指標とし、動き・タイミングの採点と並べる。従来の16値→ROI 4値の結果は入力作業の一部の測定として扱う。
- [ ] 約1分以上の素材または待ち時間の長い推論を扱う段階で、ジョブの進捗、キャンセル、再試行、失敗詳細、成果物と元リビジョンをUI/APIに出す。中断時の一時ファイル回収、再試行時の重複、GPUジョブの直列実行も確認する。

## 3. M3　関係・音・演出規則を同じ画面で確認する

- [ ] **音声の基準を確認。** `librosa` の拍・オンセット・RMSの出力は実装済み。Lyricsample1と転用先で人が拍と小節頭を聴き取り、ずれを確認する。小節頭・セクションは手入力または推定後の修正で保存できるようにする。波形、拍、オンセット、強弱、映像イベントを並べ、時間差と音声側の推定／手動の区別を表示する。
- [ ] **観察から仮説、規則へつなぐ。** `events` のブロックIDと、合字・ルビの観察をリンクする。OCR候補、確認済みの文字構成・時刻、複数の説明を画面で確認する。観察の支持例・反例、仮説の適用範囲、規則の元になったシーンとリビジョンを辿れるようにする。
- [ ] **実素材で規則を試す。** `hold_group`、`stagger`、`glyph_combine` は実装済み。ブロック・出来事・外観が同じ規則に追従するようにつなぎ、文字の順序・ルビとの同期、接触から反転までの時差、タメなし／短い／長い、合字±1Fを比較する。縮み続ける親と止まる子の組合せや、キックとの同期は現行の同値キー停止だけで扱える範囲を確認する。音声そのものの編集は、検証に必要な場合に別作業とする。
- [ ] 「拍の約90ms先行」などは、拍推定のずれと演出上のずれの両方を候補として残す。手で確認した拍と映像イベントで先行／遅延を再計測し、採用した解釈と根拠を保存する。

## 4. M4　別の実曲で受け入れ試験

- [ ] **転用先の音源を用意する。** テンポ、拍間隔、区間長の違うユーザー提供の実曲を短区間で取り込み、拍・小節頭・区間を確認する。音声取り込みと拍推定のAPIはある。工程比較から音源と区間を指定する操作は残る。
- [ ] **新しい工程の文書を変換する。** 現行の `adapt` はシーンの拍キーを対応先の拍へ移し、複数区間と親子を扱う。ブロックの外形キー・表示端・非表示区間、出来事の時刻と時間差、外観の子、規則の参照先も一緒に変換する。元の観察は元動画のSHA256と実測時刻で保存し、派生資料は対象音源に対応付ける。現状はブロック文書が元のハッシュのままコピーされ、出力側の工程比較の素材照合に失敗する。
- [ ] **区間境界と拍への対応を試す。** 区間をまたぐ背景・親・タイトル、区間境界をまたぐ補間と速度、揺れる拍での周期・文字間隔、拍欠損、頭と末尾、表示寿命とイベント順序の矛盾を確認する。秒で測った時差と拍に結びつけた関係の扱いを `adaptation.json` に記録する。
- [ ] **新しい尺・文字・素材に合わせる。** 部分的な手直し、文字数と字幅、ルビ、素材・区間長の違いを処理する。保持した関係、変えた時刻・組み方、変更理由を表示する。
- [ ] **比較基準を揃えて人が評価する。** 実装済みの「全体速度変更」「最初と最後の拍を合わせる」「固定テンプレート」に、必要に応じて各拍だけに合わせる局所リタイミングを加える。規則版と同じ音源・尺で出し、タメ・切替・読み順・音との関係を人が比較する。全体速度変更や拍合わせとの差を実例で説明でき、同じ入力・設定・リビジョンで再生成できればM4の受け入れとする。

## モデル・外部ツールの導入

| モデル・ツール | 状態 | 残作業と採用の条件 |
| --- | --- | --- |
| OpenCV・FFmpeg | 導入済み、実素材で動作確認済み | 中盤と全編に適用して比較の基準を作る。近傍探索、テンプレート照合、回転の検証を先に行う。 |
| PP-OCRv5 Mobile 認識ONNX | 重み・辞書を取得済み（合計約17MB）。CPUで5コマ検証済み | 既存環境への依存を分離し、版・ハッシュを固定。中盤とルビ、装飾字で複数フレームの候補を比較し、UIで人が訂正できるようにする。検出モデルは箱を用意できない素材が問題になった時に試す。 [公式モデル](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec_onnx) |
| SAM 3.1 | 端末に導入済みの記録とキャッシュあり。MLMとの接続、時間、ピークVRAMは未検証 | 既存環境と重みを使い、中盤の難所2〜3秒をOpenCVと同じ初期指定で比較。短い区間、モデル再利用、対応可能な精度設定を測り、初回起動と2回目以降を分ける。8GBでのOOM・ピークVRAM、欠測、取り違え、修正時間を記録。短区間で改善した場合にMLMの補助ワーカーへつなぐ。 [Metaのリリースノート](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md) |
| librosa | 拍・立ち上がり・RMSのワーカーを導入済み | 2曲で人手の拍と比較し、音声の推定と手修正を工程画面へ出す。 |
| All-In-One / All-In-One-Infer | 未導入。M3/M4の小節頭・楽曲区間の候補 | 2曲を人が付けた小節頭・区間と比較。WindowsではNATTEN依存を避けられる推論forkを先に評価する。依存・重みのダウンロード量、実時間、ピークVRAM、コードと重みの利用条件を確認する。初回M4は手動マーカーでも検証できる。 [上流](https://github.com/mir-aidj/all-in-one)・[推論fork](https://github.com/openmirlab/all-in-one-infer) |
| CoTracker3 | 条件付き候補 | 箱・マスクを取れても遮蔽前後でアンカーやIDが切れる時に点追跡を比較する。非商用条件のある配布元なので採用前に用途を確認する。 [公式実装](https://github.com/facebookresearch/co-tracker) |
| Fast Sprite Decomposition / Motion Vectorization | 条件付き候補 | 見た目のレイヤーや重なり・変形の復元に不足が残った時、`external/` の別環境で配布サンプル→同じ実素材を試す。8GBでの起動・ピークVRAM、実時間、出力をMLMへ移せるかで採否を決める。 [Fast Sprite](https://github.com/CyberAgentAILab/sprite-decompose)・[Motion Vectorization](https://github.com/sxzhang25/MotionVectorization-ProgramTransformation) |
| PySceneDetect / Demucs系 | 条件付き候補 | 前者は別素材でカット誤検出が増えた時、後者はミックスから拍を取る精度が人の修正負担を増やす時。All-In-One系の分離処理と重複する導入も確認する。 [PySceneDetect](https://github.com/Breakthrough/PySceneDetect)・[Demucs](https://github.com/facebookresearch/demucs) |
| OCR検出追加、追加書体、LayerD、scikit-image、MusiCue | 保留候補 | それぞれ検出漏れ、字形の不一致、単フレームの前後関係、FFmpegの比較指標の不足、音からの曲線生成が作業を阻害した場合に再評価。現行の日本語書体、FFmpeg、既存ワーカーで先に不足箇所を特定する。 |

モデル比較では入力ハッシュ、区間と初期指定、重み・コードの版、依存版、ライセンス、起動込み／再利用時の処理時間、ピークVRAM、欠測と誤対応、修正時間を残す。重い依存はワーカーごとに隔離し、配布元と重みを固定する。

## 横断の持ち越し

- [ ] READMEの旧記述（波形のみ、日本語フォント未登録など）と仕様書の実装状況を棚卸し結果へ合わせる。最新の未コミット差分を確認・検証し、変更単位を整理する。
- [ ] 通常編集画面の狭幅、速度曲線の表示、OSのファイル選択、Claude Desktop通常チャットの接続確認を必要に応じて行う。既存のドラッグ、タイムライン、履歴、アップロード、ゴミ箱、フレーム数は基本動作の再検証に含める。
- [ ] テストプロジェクトは現行の検証スクリプトが参照するものを確認してから整理する。履歴の容量と旧音声の蓄積は1分以上や多リビジョンで計測し、履歴から参照されるファイルを保持した上で回収・整理を扱う。

M5へ進む判断材料は、**Lyricsample1を全編で測って直せること、同じデータで中間と最終を比較できること、別の実曲で関係の保存・変更を説明できること**の三つ。研究モデルの試験結果は、その判断に効いた箇所と一緒に残す。
