# Lyricsample1 工程比較の初版

入力から、動き、関係と時刻、最終調整を同じ再生位置で比較できる。MLMで「Lyricsample1 · 工程比較」を開き、「工程比較」を押す。4画面と各工程の単独表示を切り替え、再生速度を落とす、コマを送る、出来事の時刻へ移動する操作ができる。

## 実装の判断

- 冒頭は二値化と連結成分で外形を取った。平坦な字形では特徴点が途切れたため、手で選んだ範囲ごとに前景の箱を計測した。背景の極性は画面端の輝度から毎フレーム判定した。選んだ範囲と成分の矩形を残したので、成分の取り違えを後で調べられる。
- `blocks` は箱の幅・高さと観察ID、シーンの親グループは動きのキーを持つ。`appearance` は文字などの子を親と対応付ける。箱を広げても子の文字は引き伸ばされない。冒頭の単一文字の投影幅と高さは、外観側の子に個別に適用した。
- 15Fの接触には出来事と1フレームの観察IDを付けた。16Fに再び見える「各」は同じIDを保持した。合体・分離・交代を確定する場合は、入力の終了と出力の開始を同じ時刻に合わせる。
- OCRはPP-OCRv5 Mobile認識モデルのCPU推論。すでに箱があるため、検出モデルの追加は要らなかった。15Fは目視で「略」に見え、OCRでは「路」、信頼度0.689だった。15Fの最終版には目視の読みを採用した。5コマ分の候補とモデルのハッシュを結果に保存した。 [公式ONNXモデル](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec_onnx/tree/ed152b8)
- 画面と書き出しは同じ評価関数とキャンバス描画を使う。元動画の時刻を4面で共有する。FFmpegでは4本の映像を合成してから元音声を付け、映像の末尾が音声の端数で切れるのを防いだ。

## 確認した結果

| 項目 | 結果 |
| --- | --- |
| 計測範囲 | 0～26F。4つの表示対象、47件の計測で欠測なし |
| 目視で置いた箱との誤差 | 35件。中心の中央値1.6px・最大9.8px。幅の中央値2px・最大8px。高さの中央値2px・最大15px |
| 背景の反転 | 全編で82F、93F、150F、160F |
| 4面と単独MP4 | 各183フレーム、24fps、7.625秒。元音声つき |
| ブラウザ | 4画面と単独表示、再生、15Fへの移動・16Fへのコマ送り、MP4出力 |

目視の箱は、縮小したコンタクトシートから作った概算。同じ素材で範囲も選んでいる。独立した人による採点と、直接文字を作る手順に対する工数比較は未実施。

27F以降の動きは既存シーンから補完した。反転の時刻は全編で実測した。冒頭のルビは既存の近似、字形の回転と変形は未再現。共通カメラ運動の推定、SAM 3.1による再計測、任意素材のUIからの自動ブロック分解、出来事のUI編集は未実装。

## 同じ素材で再実行

使用したモデルは配布リビジョン `ed152b8` の `inference.onnx` と `inference.yml`。両方を `data/models/pp-ocrv5-mobile-rec/` に置く。ワーカーの動作確認環境はOpenCV 4.11.0、ONNX Runtime 1.20.1のCPUプロバイダー、PyYAML 6.0.3。必要に応じて `MLM_BLOCKING_PYTHON` で既存のPython環境を指定できる。

```powershell
node scripts/verify-blocking-lyrics.mjs p_mwl57hkcq4dc data/Lyricsample1_Output_2026-11-18_103035/scene.json data/Lyricsample1_Blocking_Output
```

初回は比較プロジェクトを作る。同じフォルダーで再実行すると、前回の書き出し以降に編集されていない場合はその比較プロジェクトを更新する。出力フォルダーには4面と単独のMP4、編集用シーン、観察・出来事・外観のJSON、照合結果を出す。
