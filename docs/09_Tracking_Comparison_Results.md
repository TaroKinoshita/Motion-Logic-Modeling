## 判断の根拠

- CPUのOpenCVを専用uv環境へ分離。ユーザー承認済みのopencv-python-headless 4.11.0.86 / numpy 1.26.4を導入、uv.lockで固定。既存の別環境を変更しない。
- 特徴点のLK追跡を往復誤差で絞り、RANSACの部分アフィン推定で中心・等方拡縮・回転を得る。任意の輪郭分解を解く前に、既知の領域の移動を計測するため。参照：[OpenCV LK](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)、[部分アフィン推定](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。参照時の4.xページは4.13へ転送されるが、実装試験は固定した4.11で実施。
- confidenceは「初期特徴点に対する現在のRANSAC内点の割合」。正解確率ではない。点が不足する、往復追跡が合わない、内点が25%未満になる場合は終了。再捕捉はしない。数値計測に基づくが対象の対応は推定なのでoriginはestimated。
- 最初の近似は自作の誤差上限付き折れ線。cubic-bezierの適合を評価する基準にする。許容値はx/y各1px、scale 0.005、rotation 0.5度。保証は観測サンプルでの近似誤差であり、元動画への正確さを保証しない。
- 生の軌道をobservations.json、近似をsimplification.jsonへ分離。入力動画SHA256、解析版・パラメータ、近似元JSONのSHA256を記録。現時点ではCLI成果物であり、プロジェクトのrevision管理には未接続。既存プロジェクトやscene.jsonを変更しない。
- 比較は既存のFFmpeg SSIMをAPI化。比較用の書き出しにはUUIDを付け、並行解析が通常の書き出しを上書きしないようにした。一時動画名もUUID化。終了時に解析用動画と統計ログを除去。

## 実行して確認

- Python unittest 4件：平行移動、対象消失、不正領域/フレームレート、停止を含む近似。模様の30フレーム移動で最大位置誤差0.004150px、x/y各2キー。
- 1c合成素材のMOTIONの先頭文字領域（400,300,105,120）、1.9〜2.6秒、30fps、21点。生成コードの2.0〜2.4秒の上移動式と照合。yの最大誤差0.484840px、近似後0.484612px。x/scale/rotation各2キー、y12キー。登場時刻の正確さはこの試験の対象外。
- `node scripts/verify-track.mjs <kinetic_sample.mp4>` で再現。成果物はdata/track-validation/。
- `node scripts/verify-beats-http.mjs`：HTTPとMCPの区間比較が同値、逆転区間400、14ツールを確認。0.5〜1.5秒・640x360・30フレームのSSIM平均0.958930。revisionと元動画SHA256を返す。拍推定、手動マーカー保護、競合拒否、領域画像も再検証。
- npm test 20件、typecheck、web build、git diff --checkは成功。Python unittest 4件も成功。

## 未検証・次

追跡CLIにはFFmpegでCFR化したクリップを入力する。fpsのメタデータ一致は検査するがVFRを完全には識別しない。時刻は開始秒＋サンプル位置/fps。動画末尾の読出し失敗と破損は現状区別できない。

実素材、遮蔽からの復帰、激しい拡縮・回転・変形は未検証。現在の特徴点集合は補充せず、背景を含む領域では背景へ追従する可能性がある。SSIMは画素比較で、演出理解・カット時刻誤差・要素ごとの位置差を示さない。

次は追跡成果物とプロジェクト履歴の連携、シーン座標への変換とキー適用、cubic-bezier近似の比較、UIで不確かな追跡を確認・修正する導線。実素材受け入れとM2c完了はまだ宣言しない。
