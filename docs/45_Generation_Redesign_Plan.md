# 新曲生成の設計の作り直し計画

2026-11-20。[文書44](44_Generation_Quality_Diagnosis.md) の改修で画面統計は参考の範囲に近づいたが、見た目は参考作品から遠いまま。原因は個々の値ではなく設計にあるので、生成の方式そのものを変える。

## 1. 根本原因

これまでの生成は「手で決めた規則で、白紙から構図と動きを組み立てる」方式だった。

- 参考作品の良さは、主役の大小、先行字の保持、図形との連動、1コマの切り替え、つぶれ・回転、合字などが**一つの場面の中で組み合わさっていること**にある。規則を一つずつ足しても、この組み合わせ方は再現できない。文書44の改修も、規則を良くしただけで、この限界は越えていない。
- 一方で、解析側にはすでに**参考7本を編集可能に復元したシーン**がある。固定形＋変形キー、出来事、ブロックと外観の分離、文字差し替え（Lyricsample1〜7、文書22・23補正版）。生成側はこれをまったく使っていなかった。解析と生成が切れていたことが、最大の設計上の欠陥。
- 作家性の抽出（規則・重みの推定）は、7本・対照6本では統計的に成立していない（文書36〜38）。抽出が成功するのを待ってから生成する設計では、生成の品質は上がらない。

## 2. 新しい方式：参考の場面を部品にして、新しい歌詞へ移し替える

生成を「白紙からの構成」から「**参考の場面（パッセージ）を選び、並べ、新しい歌詞と時刻に合わせて移し替える**」方式に変える。動きと構図は参考の復元データそのものから来るので、手で決める値が大きく減る。

```
参考7本の復元シーン ──切り出し──▶ パッセージ辞書（役割・文字数・長さ・出来事つき）
                                            │
新しい歌詞＋音源 ──句に分ける・時刻合わせ──▶ 句ごとに候補を選ぶ（制約と点数）
                                            │
                              ブロック段階：参考の親キーを新しい時刻へ伸縮
                                            │
                              外観段階：新しい文字をブロックの外形に合わせて載せる
                                            │
                              4画面比較・画面統計・人の評価
```

ブロック先行の構造（文書43の修正）はそのまま生かす。参考の親グループの動きをブロックとして持ってきて、文字は外観として後から差し替える。この処理は、既存の文字差し替え（同じ親キーを保ったまま字を変える）を一般化したものになる。

### 既存の文書との関係

- 文書23の形式化（制約充足・部分集合の選択）は、**どのパッセージをどの句に当てるか**の選択に使う。理論の役割が「作家性の判定」から「生成時の選択」に変わる。
- 文書24の仮説 T1〜T7 は、パッセージの特徴（主役の有無、先行字の保持、合字、反転、変形）の分類に使う。
- 規則で作る現行の生成（文書44）は、比較の基準として残す。

## 3. 段階と合格条件

| 段階 | 内容 | 合格条件 |
| --- | --- | --- |
| **P1 パッセージ辞書** | 7本の復元シーンを、カット・出来事・語の切り替わりで区切る。各パッセージに、ブロックごとの役割（本文の主役／脇役／ルビ・訳／図形／背景）、文字数、時間長、含まれる出来事（合字・縮小・反転・回転）、復元品質（既知の誤りの有無）を付ける。役割はOCR・寸法・寿命から自動で付け、判定できないものは「要確認」にする | 全パッセージの数と内訳が出る。既知の復元誤り（文書22の8件と補正結果）を含むものは除外または印付き。各パッセージを単独で再生でき、元動画と同期比較できる |
| **P2 移し替え** | 1パッセージに新しい語と時刻を当てる。(a) 文字の割り当て：本文ブロックの順と、語の文字数を対応させる。数が合わない場合は、ブロックの分割・統合・省略の規則を持つ。(b) 時刻：語の開始時刻を基準点にした区分的な時間伸縮で、親キーを新しい時刻へ移す。1コマの切り替えは伸縮しない。(c) 外観：新しい文字をブロックの外形に合わせて載せる。図形・線は元のまま残す | 自己再現：元の文字と時刻を与えると、元の復元と同じ描画になる（差がほぼ0）。差し替え：文字数を1〜2字変えた場合と、時間を0.7〜1.5倍にした場合に、重なり・はみ出し・切れが自動検査で0件 |
| **P3 句分けと時刻** | 新曲の歌詞を句に分け、語の開始時刻を決める。まずは手入力の時刻ファイルを使う。精度が問題になったら、歌詞の強制アラインメント（lyric-align、必要ならDemucsでボーカルを分離）を導入する。導入時はダウンロード前に名前・出所・容量を示して確認する | 句と語の時刻が、ファイルとして編集・保存できる。自動推定を使う場合は、手で直した値との差を記録する |
| **P4 並べ方（選択）** | 句ごとに候補パッセージに点数を付け、曲全体で選ぶ。点数の項目：文字数と役割の一致、時間の伸縮率（大きいほど減点）、強調語と主役の一致、同じパッセージの連続回避、参考作品の中での並び方（例：大きい主役の次に組み立ての場面が来る）。文書23の形式でいう制約と重み。重みは最初は設計値とし、その旨を記録する | 全句に候補が割り当たり、理由（選ばれた候補・点数・次点）が保存される。候補がない句は、規則生成（文書44）で埋めたと明示する |
| **P5 評価** | (a) 作品を1本外した再現：参考N以外の6本の辞書から、参考Nの歌詞と時刻で生成し、本物と並べる。(b) Test_audio1 の新曲で、規則生成（文書44）と比較する。(c) 画面統計（文書44の指標）。(d) 条件を伏せた人の評価（評価者の手配だけユーザーに依頼） | (a)(b) の比較動画と数値が出る。(d) で、規則生成より「演出が参考に近い」と判定される割合を記録する。目標値は (d) の前に固定する |
| **P6 一般化** | 辞書が小さいため、同じ場面の使い回しが目立つ。パッセージの動きを正規化して型にまとめ（文書20の動きの型を拡張）、大きさ・位置・時間を変えて使えるようにする | 同じ曲の中で同じパッセージの使用回数を制限しても、全句に候補が残る |

## 4. 最初の縦切り（P1〜P2の最小版）

1. Lyricsample1・2・4 の復元から、本文の主役がはっきりした5〜10パッセージを切り出す。
2. Test_audio1 の最初の2句（「さあ 皆 舞いな 空洞で」「サンスクリット 求道系」）に、手で選んだパッセージを移し替える。
3. 規則生成（文書44）と並べた比較動画を出す。

ここで見た目が明らかに良くならなければ、P3以降に進む前に方式を見直す。判断材料は比較動画と、移し替えで崩れた箇所の一覧。

## 5. 予想される問題

| 問題 | 対策 |
| --- | --- |
| 辞書が小さい（7本・約62秒） | まず短い曲・短い区間で評価する。P6で型にまとめる。追加の参考素材があれば辞書に足す（ユーザーへの依頼は素材だけ） |
| 文字数・語数が合わない | P2の分割・統合・省略の規則。合わない度合いを点数に入れ、無理な割り当てを避ける |
| 復元の誤り（別の場面の字、図形と字の混同） | 品質の印が付いたパッセージは使わない。P1で自己再現の差が大きいものを除外する |
| 参考の動きをそのまま使うことになる | 素材はユーザーが提供した参考作品で、目的は動きと演出構成の再利用。ただし、同じ場面を丸ごと続けて使うと元作品に近づきすぎるので、P4で連続使用を制限する。P6で型にまとめた段階で、元の場面との距離を測る |
| 色・書体が作品ごとに違う | 外観段階で、曲ごとに書体と配色を統一する。色はパッセージの明暗関係（反転の有無）だけを引き継ぐ |
| 歌声との時刻のずれ | P3。手入力の時刻で始め、自動アラインメントは必要になってから入れる |

## 6. やめること

- 規則生成（`lyric-planner.ts` の構図部分）の値の微調整。比較の基準として現状のまま凍結する。
- 作家判定の精度を上げるための追加解析。新しい対照素材が届くまでは止める。
