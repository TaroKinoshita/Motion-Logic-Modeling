# 新曲生成の品質低下の診断と改修

2026-11-20。[文書43](43_Review_Handoff_Current_State.md) の時点の生成（`Test_audio1_General_Planner_v2`）がなぜ低品質だったかを、参考映像と同じ指標で測って特定し、`apps/server/src/lyric-planner.ts` の構成部分を作り直した。

## 1. 測り方

`scripts/measure-generation-gap.py`。参考7本（Lyricsample1〜7）と生成物を、同じ画面統計で比べる。480×270、約12fpsで標本化し、背景（画面端の中央値）との輝度差50以上を前景とする。前景成分を少し膨張させてブロックにまとめる。

| 指標 | 意味 |
| --- | --- |
| 最大ブロック高 | 最も高い前景ブロックの高さ ÷ 画面高（中央値、90パーセンタイル） |
| ブロック数 | 同時に見える前景ブロックの数（文字単位で分かれることがある） |
| 占有範囲 | 前景全体の外接矩形 ÷ 画面面積 |
| 変化率 | 連続する標本の間で前景が2%以上変わった割合 |
| 大変化 | 前景の6割以上が入れ替わる変化の毎秒回数 |

画面上の代理指標で、文字の意味・読みやすさ・演出の良さを直接は測らない。

## 2. 問題の特定

| 指標 | 参考7本 | 旧生成（v2） | 新生成 元歌詞 | 新生成 別歌詞 |
| --- | --- | ---: | ---: | ---: |
| 変化率 | 0.90〜1.00（中央値0.97） | **0.38** | 0.97 | 0.93 |
| 大変化（回/秒） | 5.93〜8.53（6.91） | **1.25** | 4.20 | 4.29 |
| 占有範囲 | 0.08〜0.25（0.12） | **0.36** | 0.20 | 0.13 |
| ブロック数 | 3〜7（4） | **8** | 6 | 5 |
| 最大ブロック高 中央値 | 0.13〜0.36（0.24） | 0.24 | 0.33 | 0.22 |
| 最大ブロック高 90% | 0.32〜0.93（0.58） | 0.42 | 0.35 | 0.61 |

旧生成の主な問題（数値と目視）：

1. **画面が止まっている。** 標本の6割で何も変わらない（参考は1割未満）。語が入ったあと行の終わりまで静止していた。
2. **語が積み上がる。** 行の語を全部残すので同時に8ブロック。参考は3〜7（中央値4）で、主役以外は入れ替わる。
3. **画面に散らばる。** 占有範囲が参考の約3倍。4つの固定テンプレート（左右・上下・階段・縦並び）で画面の隅まで使っていた。
4. **読む順が逆になる。** 主役を左に置き、先に歌われた語を右に並べるテンプレートがあった（例：「皆」の右に「さあ」）。
5. **強調語が大きくならない。** 脇役を同時に置くため、主役の高さが画面の3割前後で頭打ち。
6. **その他の目視**：赤い差し色と全主役の下線が一律、白黒反転が行番号の周期（3行ごと）。

参考に近かったのは最大ブロック高の中央値だけだった。文字の大きさより、**時間方向の変化のなさと、同時に出す量・散らばり方**が主因。

## 3. 改修（生成側）

ブロックを先に作り外観をかぶせる構造（文書43の修正）はそのまま使い、構成を「行ごとのテンプレート」から「語ごとのショット」に変えた。

| 変更 | 根拠 |
| --- | --- |
| 語ごとに主役を切り替える。直前の2語までを約1/2.5の大きさで残し、それより古い語は消す | 1コマで約2.5倍縮んで残る例（Lyricsample6の2区間、2.46倍・2.50倍、文書22）。ブロック数の参考値 |
| 強調語は残した語を消し、単独で大きく（最大で画面高の58%）出す。強調でない語は最大30% | 主役は一つで極端に大きい（T1、文書24）。最大ブロック高90%の参考値 |
| 中央にまとめ、主役の幅は画面幅の52%以内 | 占有範囲の参考値 |
| 行全体を連続してゆっくり拡大（行の間に1.12倍） | 変化率の参考値 |
| 語の登場は1コマで跳び、4コマで落ち着く（横6%、拡大1.06倍） | 急に入って止まる例（Lyricsample2の77〜87F、文書21） |
| 残した語の置き方を行ごとに「上」と「横」で交互にする。横は幅が収まらなければ上に戻す | 設計値。参考4の横並びを参考 |
| 8文字を超える語は小さく残さない | 1/2.5では読めない。設計値 |
| 行の頭で、前の行の最後の語を小さく短時間残す（従来の持ち越しを維持） | T2（文書24） |
| 単色（差し色と下線をやめる）。反転は強調語のある行を1行おき以下 | 参考の大半が単色。反転規則は設計値 |

ブロック版（`*-blocking.mp4`）は同じ親グループのキーで動く矩形で、最終版は同じ親に文字を子として載せたもの。動きのキーは親だけが持つ。

## 4. 確認したこと

- 元歌詞・別歌詞とも336コマで、本文の重なりと画面外へのはみ出し0件。同じ入力から同じシーンになる。
- 範囲検査32条件：24生成・8拒否（50文字の語。旧版と同じ件数）。
- `npm test`（32件）、`npm run typecheck`、`npm run build` が通る。
- 目視：「皆」「鼓動」「空」が単独で大きく出て、次の語が来ると小さく上に残る。読む順は上から下。

## 5. まだ足りないこと

- **大変化の回数が参考の6〜7割**（4.2回/秒、参考は5.9〜8.5回）。語の時刻でしか切り替えていない。音の立ち上がりで主役を揺らす・縮めるなど、語の間の変化はまだない。
- **元歌詞の強調時の高さ90%値が0.35**。強調語が短時間しか出ないため。別歌詞では0.61。
- 漢字の部品の合体、図形との組み合わせ、回転・つぶれなど、参考の見せ場は生成に入っていない。
- 値の多くは設計値で、参考から学習した重みではない。作家らしさの評価、歌声との同期、人による品質評価は未実施。
- アプリ画面からの生成操作は今回確認していない（関数とスクリプトで確認）。
