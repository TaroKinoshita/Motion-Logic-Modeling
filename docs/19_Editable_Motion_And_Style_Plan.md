# 編集できる動きから演出規則を作る計画

最初の成果物は、Lyricsample1の冒頭で「各」を別の文字に差し替えても、流し・横のつぶれ・停止・出入りの時刻が保たれる比較版。同じ区間に、人が確認した発音・拍・映像イベントを並べる。これを通してから、複数作品で繰り返す動きや演出を規則にする。

現行の全編版はトレースの比較基準として使う。「飯」の82〜89Fでは、Fast SpriteとVTracerで固定輪郭1個・37キーの別版を生成済み。同区間の前景IoUはトレース版0.979、代表形版0.663。文字差し替え、接触前後のID維持、規則の転用は別の検証項目。 [代表形版の実測](18_Vectorization_Tools.md)

## 1. 実装順と各段階の合格条件

| 段階 | 実装と成果物 | 合格条件 |
| --- | --- | --- |
| A. 短区間の基準 | Lyricsample1の冒頭3〜26Fを対象に、元映像・トレース版・人が独立に付けた注釈を揃える。対象文字の表示端、15Fの重なり、16F以降の再出現、追跡できないコマを記録する。歌詞と拍は前後も聞き、確認できる発音の開始と終わりを付ける | 元映像だけから採点できる注釈が揃う。歌詞や対象の対応が判別できない箇所も記録する |
| B. 代表形と差し替え | 「各」のIDを接触前後で確認し、固定輪郭か編集可能な文字を同じ親の動きに結ぶ。「各」の代表形版と、別の字にした版を同期比較できるようにする。動きの途中に1フレームの接触がある場合は、その観察をイベントとして残す | 同じ親の変形キー・表示端・イベント時刻を使って再生・保存・再出力できる。形状変更で接触位置が変わった場合はその差を報告できる |
| C. 動きと発音の観察 | 手動の発音、拍・小節頭、既存のオンセット／RMSを映像の出来事と同じタイムラインに置く。停止・加減速・登場順を元の観測から測り、キーの候補と照合する。「食＋反→飯」81〜93Fと「何にも」150〜159Fで、切替と回転も別に確認する | 発音・拍それぞれへの符号付き時差と根拠が読める。回転は角度キーとして評価でき、見分けられない項目は欠測として出る |
| D. 作品を増やす | 同じ作家の作品を2〜3本、対照作家の作品を1〜2本追加する。注釈の語彙、作品のクレジット、採点の揃い方を確認してから、必要に応じて同じ作家5〜10本へ広げる | 作品をまたいで同じ定義で測れる。別作品でも現れた条件、対照でも現れた条件、例外を示せる |
| E. 新曲へ生成 | 新しい歌詞と音源に、区間ごとの見せ場・ルビ・反転・字の見立てを割り当てる。規則からパラメータを選び、既存シーンへ変換する。規則あり・なし・規則を1つ外した各版を出す | 同じ入力、規則の版と設定から再生成でき、評価に使う別の実曲で演出の差を比べられる |

Aの独立した注釈と、D・Eの追加素材は人と素材の協力が要る。Bの実装、既存音源を使うCの計測、合成素材でのEの接続テストは手元のデータで進められる。別の実曲を使う受け入れ試験とM5出力は、従来どおり実装作業の区切りから外す。

## 2. 動き、外観、出来事の保存

- **対象と観測を分ける。** `blocks` のIDは文字・部品・ルビなど、編集したい単位に付ける。元の短い追跡IDや観察ID、紐付けの時区間、手動確認の有無を残す。接触前後は位置・速度・大きさ・形状の比較で対応を提案する。短い寿命の要素も、実際の1フレーム表示と追跡断片を区別する。似た候補が複数なら未確定のまま点検へ回す。
- **重なり中の状態を記録する。** 接触や遮蔽で見えなくなっても同じ対象が戻る場合は同じIDと欠測区間を保存する。部品が別の結果に交代した場合は、元と結果のID、時刻、根拠を `events` に保存する。「略」に見える理由と、追跡上のIDの対応は別の注釈を持つ。画面の切替と一時的な接触で同じリセット処理を使わない。
- **外観差し替えで時刻を保持する。** 親に位置・回転・拡縮などの変形キーと表示時刻、子に輪郭か文字を持たせる。墨付き領域を基準にしたアンカー、基準幅・高さ、文字の配置を規定し、差し替え元と先で同じ基準を使う。文字幅、穴、接触点の変化は画面で確認する。見かけの横つぶれは横倍率で記録し、画面内回転と区別する。
- **キー近似を元の観測で採点する。** OpenCVの位置合わせを基準に、現行トレース、代表形＋折れ線、代表形＋既存cubic近似を同じ条件で比較する。停止の端や切替コマを固定点にし、許容誤差を振ってキー数との関係を出す。欠測を補間した場合は推定と分かるようにする。Fast Spriteは同じ短区間の比較候補、VTracerは代表形の輪郭の比較に使う。SAM 3.1は接触前後の分離が詰まった箇所で、既存環境から実行できることを確認してから試す。

初回の判定目安は、中心の誤差中央値が画面対角の1%以内、幅・高さの相対誤差中央値が各10%以内、主要イベントが±1F以内。1Fだけのイベントは完全一致も見て、欠測・ID取り違え・最大誤差を併記する。差し替え前後で親キーとイベントが一致するかは自動検査し、最終画面で速度感と読みやすさを確認する。前景IoUは同じ文字・同じ区間の再現度に使う。別の字にした版は速度、表示・接触時刻、軌道の一致で評価する。

既存のアプリ内比較で、元動画・中間①（ブロックの動き）・中間②（出来事と時刻）・代表形または差し替え版を同じ再生位置で確認できるようにする。停止中に1Fずつ送り、出来事を選ぶと対象と参照フレームに移動できるようにする。同じ区間を比較動画にも書き出す。トレース版は数値の基準として同区間を保持する。

## 3. 音声の時間軸と注釈

元動画のタイムラインを共通の時計にする。映像イベントはフレーム番号と元FPS、音声イベントは秒と区間幅を保持する。抽出音声の開始が映像からずれる場合はオフセットを保存する。推定マーカーは、人が確認した時刻と併存できるようにする。

| 種別 | 保持する内容と初版の扱い |
| --- | --- |
| 歌詞・発音 | 歌詞の行または語のID、表記・読み、開始／終了、確認者、時刻の不確かさ。最初は短区間を手で採点する。文字・子音単位は聞き分けられる箇所に限定する |
| 拍・小節・区間 | 拍番号、拍・小節頭の区別、区間名、元時刻、手動／推定の出所。既存librosaで候補を出し、短い抜粋で判別できない区間名は保留する |
| 音の特徴 | 既存のオンセットとRMS、必要な帯域のエネルギー、ボーカルの休止とミックス全体の休止。窓長・ホップ・音源またはステムの出所を残す |
| 映像の出来事 | 対象ID、観察タグ、開始／終了、元F、確信度。初版タグは登場、停止、反転、接触、分解、合体、ルビ、見立て。見立てには人の解釈と根拠を付ける |

歌詞・音声の注釈と照合結果は `observations` に記録し、映像の `events` と音声注釈をIDで参照する。既存の拍マーカーから取得した候補には、そのマーカーのIDか時刻と計測時のリビジョンを残す。手で時刻を修正した結果は計測前の値と照合できるようにする。

`measure-events` の最寄り拍照合を基準とし、同じ映像イベントを発音・拍・小節頭・オンセットの候補へそれぞれ照合する。先行は負、遅延は正。参照候補のID、時差、誤差幅と代替候補を保持し、両方に近いものは「区別不能」とする。イベント種類ごとの分布を見て、候補の出現密度と局所テンポを保った時刻ずらしにも同程度の一致が出るかを比較する。拍や子音の密度が高いことだけで一致が増えるケースを識別する。音の強弱と動きは、共通の時間窓でRMS・帯域と速度・占有率・出入りの数を比較し、候補の先行／遅延と元区間を記録する。

### 音楽解析ツールを採用する条件

1. 先に手動の短い発音注釈と既存librosaを使い、発音対拍を評価できるか確認。
2. 小節頭にズレが残れば、Beat This!とlibrosaを人の拍・小節頭に照合。採用機種の時間とメモリも測る。 [Beat This!](https://github.com/CPJKU/beat_this)
3. 行・語タイミングの入力時間が主因なら、lyric-alignを試す。まずミックスで計測し、利用できる分離ボーカルかDemucsで得たステムと比較する。誤差・未対応率・修正時間を出し、文字時刻の補間を明示する。ドラムステムからキックとスネアを主張する場合は別途ラベルや検出を用意する。 [lyric-align](https://github.com/ijuinryukichi/lyric-align)・[Demucs](https://github.com/adefossez/demucs)
4. 十分な長さの曲で区間分類の手修正が負担になったら、All-In-One推論forkを試す。コードと重みの利用条件、配布元、版、容量、8GB機での時間とピークVRAMを候補ごとに記録する。 [推論fork](https://github.com/openmirlab/all-in-one-infer)

## 4. 作品をまたぐ規則と生成

既存の `observations → hypotheses → motion_rules` を使う。各観察は元の作品ID・リビジョン・時刻を指す。複数作品を集計するスタイル文書からは、`projectId`・`revision`・`observationId` の組で根拠を参照し、作品一覧と集計条件を持つ。同一作家として扱う根拠に、映像担当や共同制作のクレジットも保存する。

1. **動き**。登場・停止・方向転換・加減速・つぶれ方と、その区間長。
2. **時間**。拍、発音、小節頭、休止、曲の区間と映像イベントとの対応。
3. **画面**。文字とルビのサイズ比、余白、占有率、色・反転、出入りの密度。
4. **発想**。分解・合体・言葉遊びといった人による解釈、対象の字、演出の成り立つ条件。

各規則に対象とするイベント、条件、単位（秒／拍／画面に対する比）、値の範囲または選択肢、根拠になった作品・事例数、例外、確定の状態を持たせる。ある効果の回避を候補とする場合は、その効果を選べる場面の数も測り、観察機会が少なければ保留する。観察された範囲と、生成時に許可する範囲は別に記録する。既存の `hold_group`、`stagger`、`glyph_combine` は規則を実行する部品として再利用し、対象IDや音声の参照時刻を渡す。

新しい曲では、区間・歌詞・拍から見せ場を計画し、条件に合う動きと値を選び、既存のシーンと `drawFrame` で描画する。LLMを使う場合は見立てや構成の候補を出す役割とし、人が採用した候補と理由を保存する。生成結果には適用した規則の版、時刻合わせ、選択値、手修正と理由を記録する。

## 5. 受け入れ評価

- 確認用の作品は規則を作る作品と分ける。作家内でも複数の曲・制作時期を含め、対照作品はジャンル・尺・見せ方が近いものを選ぶ。小標本の段階は事例数、作品数、例外を開示する。
- 新曲の同じ歌詞・音源・画面素材で、全体速度／拍合わせの基準、規則あり版、重要規則を1つ外した版を作る。出力順と条件を伏せ、参考作品との演出の近さ、歌詞の読みやすさ、タイミングを別々に評価する。本物と見分ける試験は補助とする。
- モデル評価には要素・キー・形の数、観測との時間差、位置・サイズの誤差、欠測、手修正回数と作業時間を残す。作家性の主張は、複数作での観察と、規則を変えた比較で実際に確認できた範囲に限定する。

Bでは輪郭の箱を固定形状の変形に近似した。2pxの許容誤差で折れ線56キー、cubicを許す場合は46キー。近似に使った箱への中心誤差は中央値0.70px・最大2.0px。幅と高さの誤差は最大でそれぞれ0.60%・0.59%。形が異なると動きの再利用も評価しやすくなるため、登録済みのYu Gothicから墨付き範囲を計測し、子だけで位置と大きさを合わせた。2本の比較動画は `data/Lyricsample1_Editable_Output/`。この区間の再構成対象は「各」1字で、15Fの接触は元動画上の観察として表示する。

同じ「各」の輪郭を元動画の前景と比較すると、観測23コマでIoU平均0.650、最小は横つぶれが大きい6Fの0.222だった。4面MP4の960×540ペインを輝度128で二値化し、元映像側は対象の箱の内側を比較。15Fは欠測のため除外した。位置と幅は追従していても、横つぶれ中の字形の変形は単一輪郭の縦横拡縮で再現しきれていない。

ブラウザでは4画面、15Fへのジャンプ、16Fへのコマ送り、発音の注釈フォームと時差表を確認。`npm test` 31件、`npm run typecheck`、`npm run build`、`node scripts/verify-block-workflow.mjs` を実行した。新規のモデルダウンロードは不要だった。

## 7. 追加実装と納品物

実素材を追加しての比較と発音の採点は、ユーザーが素材を送る最後の工程に回す。実装・動作確認にはLyricsample1と合成音源を使った。出力は `data/Lyricsample1_Phases_Output/` にまとめ、`report.json` に再生プロジェクトとリビジョンを記録した。

| フェーズ | 実装と実測 | 素材・人の評価を使う作業 |
| --- | --- | --- |
| A–B | 「各」に固定輪郭1個のまま回転・せん断を追加。元映像の観測23コマで前景IoU 0.650→0.703、6Fは0.222→0.361。キーは46→84。15Fは拡大した元映像から3点を読み、16Fの「田」を変形して「各」と別レイヤーで合成した。15Fの対象領域内で両文字を合わせたIoUは0.632。「右」へ差し替えて親のキーと出来事が保持されることを確認した | 独立した採点と作業時間の計測。今回の目視採点で15Fの「各」は中心5.5px、幅11.1%、高さ11.6%の誤差。対象を指定した短区間の検証で、全183コマの編集可能な再構成や極端な横つぶれは引き続き別の作業 |
| C | 「何にも」の150〜159Fを3枚の固定輪郭と共通の親で描画し、31.4°の回転を5キーに圧縮。停止・速度・加速度・箱の占有率と表示中のブロック数を保存し、16〜26Fの「各」で20〜22Fの停止候補を計測。RMSとの時差別相関と、音の候補列をずらした対照を記録 | 人が確認した発音、採点者間の一致、楽器の同定。Lyricsample1で拍に近いイベントは8件、位置をずらした5条件では4〜8件。拍合わせの意図を示すには追加の根拠が要る |
| D | 作品とリビジョンを固定した観察から、動き・時間・画面・意味の4軸を集計。画面は箱の占有率とブロック数、意味は合字・ルビの注釈範囲と合字の部品数を指標にした。実素材の「食＋反→飯」2部品で保存と集計を確認 | 同じ映像担当と対照担当の追加作品、クレジットの確認、作品ごとの規則と例外の照合 |
| E | 新しい歌詞と手入力の区間を使い、入り・タメ・文字の時間差・反転・合字を同じシーン形式に変換。合成音源で、基準・全規則・それぞれ1つ外した7本を同じ音源・歌詞で出力 | 規則の選別と評価。生成用のタグ・曲区間・歌詞・合字部品は指定が必要。比較には合成音源と試験用の範囲を使用した。新しい実曲の受け入れとM5は保留 |

アフィン近似は輪郭のIoUが小幅な改善なら軸方向を優先し、細い箇所だけ左右反転も候補にする。位置の追従と見た目の改善を確認するため、近似に使った形同士の照合に加え、元映像と書き出しを別に比較した。採点用の箱は `block-checkpoint` に保存し、代表形の計算に含めない。時刻ずらし試験は同一区間内で循環させて件数と候補間隔を保つ。既存のlibrosa推定を使い、今回は追加モデルを導入していない。

`03_contact.mp4` と `04_contact_replaced.mp4` は接触の見え方、`05_rotation.mp4` は回転、`07_lyric_comparison.mp4` は7つの生成条件を同期した比較。評価する人に条件を伏せる場合は、MP4とA〜Gの記号を使い、条件表 `generation_conditions.json` は集計担当者が保管する。

## 8. 全183コマの編集モデル

計測済みの工程比較に全編変換のジョブを追加した。1軌道につき最大4区間とし、各区間に代表輪郭を1つ置き、同じ親の移動・拡縮・回転・せん断を編集できるようにした。1つの形で全編をまかなう初版では、追跡IDが「丁」と「ん」にまたがると両区間に同じ字が出た。正規化した輪郭の重なりが十分改善する場合だけ、4観測以上の区間に分けて形を切り替える。候補の切り替えを出来事に残す。接触と回転は既に確認した区間を同じ全編に組み込み、「各」は15Fをまたいで同じ親IDを使う。

短い追跡断片の接続には、カットをまたがず、前後の位置・寸法・濃淡と輪郭が一致し、双方から見て候補が一意に近いことを条件にした。既存の出来事が参照するIDは自動接続から外した。Lyricsample1では自動接続は1組。2コマ以下のブロックは108個から101個となり、短時間だけ実際に出た要素と追跡の断片の識別は引き続き必要。

| 比較 | 元動画との前景IoU平均 | 前景のコマ間変化IoU平均 |
| --- | ---: | ---: |
| 1,100枚の輪郭を使うトレース | 0.928 | 0.749 |
| 追跡IDごとに1形状を割り当てた初版 | 0.737 | 0.522 |
| 区間外観を含む自動生成 | 0.856 | 0.622 |
| 接触と回転を再構成した全編編集モデル | 0.852 | 0.618 |

全編モデルは固定形状201個、変形キー1,866個、フレーム別輪郭0。トレースでは変形1,542キーと外形1,353キーを合わせて2,895キーだった。映像の比較は24fps・183コマ。背景の端の中央値から輝度差50以上を前景とし、両版が空のコマを平均から除いた。全画面の前景IoUは6Fで0.689、15Fで0.650、35Fで0.897。6Fの全画面の値は、以前の「各」の箱内だけの値と測定範囲が異なる。最後の自動変換は5.9秒で、既存の輪郭計測・書き出し・人の手修正はこの時間に入らない。人の作業時間の削減量は未計測。

出力先は `data/Lyricsample1_Full_Model_Output/`。`full_comparison.mp4` は元動画、動き、関係と時刻、最終調整を同期した4面比較。`combined.mp4` は編集モデルの描画だけ。`report.json` にコマ別の指標とアプリで開くプロジェクトIDを記録した。`source_review.jpg` と `review_checkpoints.csv` は別の人が元動画だけから座標を付けるための資料。採点用の箱は《元映像の箱を別に採点する》に入力し、近似には使わない。

手作業の時間を検証する場合は、同じ区間・同じ再現項目を対象に、手作業での組み立てと全編モデルからの修正を比較する。操作開始から初回書き出しまでの人の作業秒数、計算待ち秒数、形状の交換・ID修正の数をそれぞれ記録する。区間は入りと接触を含む3〜26Fと、共通回転を含む150〜159Fから始め、比較順の影響を記録する。追加作品と発音時刻の検証は素材の提供後に行う。

## 9. 元ファイルからの再テスト

元の `Lyricsample1.mp4` を新規プロジェクトに取り込み、同じカット・接触・回転の検証設定で計測からやり直した。拍推定は126.05 BPM、映像内の推定拍は16個。FFmpegの閾値10でカット候補は82、93、150、160F。輪郭観測は1,100件で、全編モデルの183フレームの前景IoUとコマ間変化IoUはいずれも前回と一致した。6F・15F・159Fの前景IoUはそれぞれ0.689、0.650、0.704。

再生成したモデルの別プロジェクトで、3〜26Fの「各」の外観4区間を「右」に差し替えた。全183フレームで対象の親変換が一致し、表示区間、イベント時刻、編集範囲外の描画データも一致した。15Fで「田」と重なる位置は保たれ、合字の見え方は字形に応じて変わった。ルビと音声は元のまま。出力は `data/Lyricsample1_Retest_Output/` の `model/full_comparison.mp4` と `replaced_full_comparison.mp4`。`source.json`、`model/report.json`、`substitution_report.json` に条件と結果を記録した。
