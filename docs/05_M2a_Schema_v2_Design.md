# M2a：スキーマv2設計案

作成：2026-11-17。状態：**承認済み・実装済み（合成素材で検証）**。実装上の制約・検証結果は [06_v2_Implementation_Results.md](06_v2_Implementation_Results.md)。本文は設計時の意図を保持する。
関連：計画仕様書 §4.3、作業指示 Phase B、受け入れ試験結果 §2–3。

## 1. 目的と範囲

文字ごとの時間差と拍ごとの繰り返しを、展開済みの大量のキーではなく関係として保存する。
今回の対象は文字・単語分割、時間差、一定テンポの拍時刻、繰り返し、アンカー、フォント。
既存の秒指定とv1シーンを保持する。可変テンポ、小節表記、ランダム順序、粒子、親の不透明度継承は後続課題とする。

## 2. 提案する形式

### 時刻と長さ

- 絶対時刻 `Time = number | { beat: number, offsetSeconds?: number }`。
- 長さ `Duration = number | { beats: number }`。数値は従来どおり秒。
- シーンに任意の `tempo: { bpm: number, offset: number }` を追加する。bpmは正、offsetは「拍0」の秒時刻。
- 拍は0始まりの四分音符単位。小数を許す。拍時刻は `tempo.offset + beat * 60 / bpm + offsetSeconds`。
- 拍による長さは `beats * 60 / bpm`。長さにはtempo.offsetを足さない。
- 拍指定があるのにtempoがないシーンはエラー。BPMの既定値を勝手に補わない。
- `Key.t` と要素の `inPoint/outPoint` はTimeを許す。scene.durationとマーカー時刻は秒のまま。
- 計測値は秒で保存し、推定拍に丸めない。拍表現を選んだキーだけがテンポ変更に追従する。
- 拍と秒を混在させた結果、キー順や表示区間が逆転した場合は更新を拒否する。テンポ変更で動画やシーン尺は自動的に伸縮しない。

### 全体の動きと文字単位の動き

text要素に以下を追加する。

- `split: "char" | "word"`（省略時は現行どおり一括描画）
- `stagger: { interval: Duration, order?: "forward" | "reverse" }`
- `unitTransform: Transform`（文字／単語ごとの局所的な変換）
- `letterSpacing?: number`（px。既定0）
- `fontFamily?: string`（省略時は現在のフォントスタック）

既存のtransformはテキスト全体に一度適用し、遅らせない。unitTransformだけを順序番号×intervalだけ遅らせる。
unitTransformのキーもシーン絶対時刻で書き、評価時に時間差を引いた時刻でサンプリングする。
単位の位置は「組版位置＋unitTransformのx/y」、拡縮・回転はその単位の中心を基準にする。
全体の表示区間で最後にクリップする。初期表示を隠す場合はunitTransform.opacityの先頭値を0にする。

例：MOTIONの6文字は登場だけ0.06秒ずつずれる。2.0秒からの全体の上移動は全員同時。

```json
{
  "id": "motion", "type": "text", "text": "MOTION",
  "fontFamily": "MLM Arial", "fontSize": 120, "fontWeight": 700,
  "split": "char", "letterSpacing": 4,
  "stagger": { "interval": 0.06, "order": "forward" },
  "transform": {
    "x": 640,
    "y": { "keys": [
      { "t": 2, "v": 360, "ease": "easeInOut" },
      { "t": 2.4, "v": 250 }
    ] }
  },
  "unitTransform": {
    "y": { "keys": [
      { "t": 0.2, "v": 120, "ease": "overshoot" },
      { "t": 0.55, "v": 0 }
    ] },
    "opacity": { "keys": [{ "t": 0.2, "v": 0 }, { "t": 0.32, "v": 1 }] }
  }
}
```

これは形式の説明用であり、生成元とのイージング・組版一致を検証したシーンではない。
splitなしのstagger/unitTransform、text以外への文字用フィールドは拒否する。
splitの削除はupsertElementで要素を置換する（現行patchには削除表現がないため）。

### 組版と描画の一致

- charはUnicodeの書記素単位。結合文字や絵文字をコードポイントごとに破壊しない。
- wordは最初は空白区切り。空白の幅は残すが時間差の順序には数えない。日本語の形態素分割は対象外。
- charでは空白も配置と順序の1単位に数える。タイプライターの空白にも待ち時間が生じる。
- 初期対象は横書き一行。分割文字列に改行があればエラーにする。高度な組版は未対応と明示する。
- 全幅を測って中央配置し、単位を配置する。描画、当たり判定、選択枠で同じ計測結果を使う。
- coreに文字計測のインターフェースを置く。ブラウザとサーバーのCanvas計測を注入し、純粋な評価処理からOS依存を切り離す。
- 同じフォントファイルをブラウザで読み込み、サーバーで登録する。指定フォント未解決のまま成功として比較しない。
- シーンにはフォント名のみ保存する。任意のローカルパス／外部URLをシーンから読み込ませない。
- まず端末のArial Boldを使ったローカル検証を想定。配布物へのフォント同梱は別途条件を確認する。
- スキーマ上のフォント指定だけでは字幅の一致は保証できない。Pillowで生成された元映像との差も別途評価する。

### 繰り返し

キー付きトラックに `repeat: { every: Duration, count?: number, until?: Time }` を追加する。

- 最初のキーの解決済み時刻を反復の開始時刻とする。
- everyは正。countは初回を含む正の整数。count/untilの併記は拒否する。
- count/until省略時はシーン末尾まで。untilは排他的な終了時刻とする。
- 1周期内のキーは最初のキーを起点とした相対時間として繰り返す。キーの範囲が周期を超える指定は拒否する。
- 周期内で最後のキーに達した後は、その値を次の周期まで保持する。
- 周期境界は次の周期の先頭値。終了後は終了直前の状態を保持する。終了境界の値を単体テストで固定する。
- 毎フレーム大量のキーを生成せず、評価時刻を該当周期へ写して評価する。タイムライン用の展開は表示区間に限る。

例：tempoが120BPMのとき6秒から4回脈動するscaleXトラック。100BPMでは7.2秒から始まる。

```json
{
  "keys": [
    { "t": { "beat": 12 }, "v": 1 },
    { "t": { "beat": 12.25 }, "v": 1.3 },
    { "t": { "beat": 12.5 }, "v": 1 }
  ],
  "repeat": { "every": { "beats": 1 }, "count": 4 }
}
```

### アンカー

要素に固定値の `anchorX/anchorY` を追加する。従来のローカル原点（要素中心）からのpx、既定0。
位置x/yをアンカーの親座標上の位置とし、行列は `T(x,y) R S T(-anchorX,-anchorY)`。
既存要素はアンカー0なので変わらない。AEへの変換では中心原点からAEの座標系へ変換する。
アンカー位置と幾何学的中心を区別し、回転ハンドルの基準・選択枠・軌道の意味を合わせる。

## 3. v1互換性と編集

- v1を検証してからメモリ上でv2へ移行する。読み込みだけではファイルを書き換えない。
- 次の明示的な変更をcommitした際にv2で保存し、projectのschemaVersionも更新する。
- 履歴のv1は保持する。巻き戻し時も同じ移行関数を通し、新しいリビジョンとして保存する。
- 未知のバージョンは拒否する。v1用スキーマは固定し、v2変更に巻き込まない。
- 分割後の単位は評価結果だけに存在する。sourceIdとunitIndexで識別し、元要素idと混同しない。
- 単位をクリックすると元のテキスト要素を選択する。ドラッグは全体のtransformを変更する。
- 選択した単位の軌道を表示し、全体操作用の選択枠も表示する。
- タイムラインは展開した単位のキーを読み取り専用で示す。JSON編集で関係自体を変更する。
- 既存の秒キーのドラッグは維持。拍キーや反復・単位キーを秒へ暗黙に焼き込むドラッグは許さない。
- opsの値変更処理が現在 `{keys: ...}` を作り直す点に注意。repeatを消さないようメタデータを保持する。
- MCPツール数は増やさず、get_guideとsetScenePropsを更新する。

## 4. 実装順と検証

1. v1移行、Time/Duration解決、拍・秒混在の検証。
2. repeat評価、終了・周期境界、テンポ変更時の整合性。
3. アンカー行列と操作座標。既存の親子操作を回帰確認。
4. フォント登録・計測経路、splitとunitTransform、当たり判定・軌道。
5. UIの読み取り専用展開、MCPガイド、API保存・履歴の移行。
6. 合成サンプルのv2版を別プロジェクトに作り、v1を保持して比較する。

各段階でcoreテストと全体型チェック。最後にブラウザ、MCP、画像・動画出力を実行する。
主な回帰試験：v1の任意時刻の評価値、全体移動と単位遅延の分離、逆順、結合文字、秒オフセット、反復境界、アンカーを持つ親子、履歴復元。

受け入れ基準：

- v1基準プロジェクト `p_mwh3s99t2w85` は2026-11-17に読み取りで確認：revision 5、44要素、コンパクトJSONのUTF-8サイズ18,233 bytes。資料の22KBは初版の数字であり、このサイズと直接比較しない。
- MOTION・LOGIC・NEW SONGの文字要素群をそれぞれ1要素で記述する。要素数とコンパクトJSONのUTF-8バイト数を同じ条件で比較する。
- 元動画に対する各区間SSIMが、v1の再計測値から概ね0.01以内。SSIMだけで登場順・タメの保持を判定しない。
- 120→100BPMでbeat12のイベントが6.0→7.2秒へ移る。秒指定イベントは変わらず、元動画の音声も変わらない。
- 不正なテンポ変更は理由付きで拒否する。表示範囲外へ出たイベントを把握できる。
- 新曲への再構成や実素材の分析ができたという評価には使わない。

## 5. 後続の試験について分かったこと

サンプル生成コードでは4.0〜4.5秒にキックが止まるが、ライザー音が存在する。
ground_truthのbeatsには4.0秒も含まれる。拍推定は音楽的な拍を推定するため、キックの不在と別に評価する。
M2bではテンポ・拍の誤差と、立ち上がり／音種の不在を区別する。全体の強弱だけでキックの不在を断定しない。

## 6. 確認する設計判断

提案：**全体transformとunitTransformを分離し、一定テンポの拍表現＋秒オフセットを導入する**。
初期の順序指定はforward/reverseに限定する。2026-11-17の実装継続指示を承認として着手した。
