# Lyricsample1「食＋反→飯」の動きと演出規則

元プロジェクトは `p_mwl57hkcq4dc` のリビジョン8。`node scripts/verify-lyrics-meshi.mjs` で、独立した検証プロジェクト、数値（`meshi-report.json`）、音声付きMP4を `data/lyrics-validation/` に生成する。

## 観察から修正した点

24fpsの81フレーム目（3.375秒）で、小さい黒字の「飯」とルビが出る。82フレーム目で白黒が反転して字が横に広がる。次の1フレームで横幅が急に縮み、終盤では広がりながら縦に潰れる。92フレーム目に細く潰れた白字の「食反」が現れ、93フレーム目で白地に戻る。

旧版は合体と反転を同時に切り替え、反転後はほぼ等方に縮めていた。反転前の「飯」とルビ、反転末尾の「食反」を追加し、ルビの色と位置を調整した。反転後の10フレームは、文字の位置と横縦それぞれの拡縮に計測キーを入れた。ウェイト400も試したが、同区間の平均SSIMが0.9341から0.9277へ下がったため700を採用した。

`track-region.targetElementId` で観測した重心・幅・高さを既存文字へ直接適用できる。描画フォントのインク領域から倍率とアンカーを求める。表示区間と追跡範囲を一致させ、親なし・分割なしの文字に限定する。区間末尾まで追跡できなければ適用を拒否する。回転は0で適用する。

## 手作業の測定

目測・計測の両版で切替時刻、字形、ルビを揃えた。目測版は事前に用意した480pxの目盛り付き画像から、Codexが4コマの中心X/Y・幅・高さを読んだ。計測版は最初の領域と白字指定から10コマを欠測なく追跡した。

| 同じ10フレーム | 目測から書いた版 | 計測から生成した版 |
|---|---:|---:|
| 位置・寸法の入力値 | 16 | 0 |
| 初期領域の入力値 | 0 | 4（左・上・幅・高さ） |
| 出力キー数（対象文字のみ） | 16 | 16 |
| 全編の要素数 | 63 | 63 |
| 幅の平均絶対差（しきい値で測った外接矩形に対して） | 33.10px | 0.42px |
| 高さの平均絶対差（同上） | 16.40px | 2.75px |
| 平均SSIM | 0.9287 | 0.9341 |

目測値の読み取りは1回で約6秒（01:04:13〜01:04:19 UTC）。追跡からキー保存までは約0.9秒、計測版の初回目視は約3秒（01:08:02〜01:08:05 UTC）。範囲選び、コード作成、画像準備、追加調整は含まない。工程が異なるため、人が編集画面で作業する場合の時間や短縮率は未計測。確認できた削減は、コマごとの位置・寸法16値を読む工程が、初期領域の4値指定に置き換わったこと。外接矩形は計測版の入力にも使ったため、誤差は独立した正解に対する精度ではない。

71〜92フレーム目の切替全体では、平均SSIMが既存の切替補正版0.9167、4コマ目測版0.9342、計測版0.9367。旧版60要素から3要素増えた。全編出力は183フレーム・7.625秒・音声付きで確認した。

## 観察から比較版を作る

`observe-glyphs` に合体時刻 `combineAt` と部品・結果の要素IDを保存する。`glyph_combine` 規則は、採用した仮説と、その仮説が参照する該当観察を使う。`variant.seconds` で部品の登場間隔、`order` で順序、`mergeOffsetSeconds` で合体時刻を変更する。各部品のルビは部品と同時に現れる。合体後の字・ルビ・反転背景・末尾の潰れは互いの時差を保って移動する。図形としての合字の連続変形は、部品と結果レイヤーの切替で近似している。

実素材で、観察どおりの切替、反→食の順で2フレーム空ける版、合体を1フレーム早める版を生成した。切替全体の平均SSIMはそれぞれ0.9367、0.9371、0.8981。逆順の版が僅かに高く、画素指標だけでは言葉遊びの読みやすさを決められなかった。早めた版の最低値は0.5932で、反転の時刻ずれが目立つ。

API/MCPの統合試験で、部品の順序、結果の開始、キー、付随ルビが指定どおり変わり、生成元のリビジョンが変わらないことを確認した。参照できない観察や範囲外の時刻も拒否する。core 28件、型チェック、ビルド、統合試験に成功。
